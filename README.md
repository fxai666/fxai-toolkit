# ComfyUI - 凤希全能节点包 产品说明书
## 一、产品概述
### 1.1 产品定位
ComfyUI - 凤希全能节点包是**ComfyUI生态专属、主打低配设备友好的AI长视频全流程解决方案**。工具集内置全套自研节点，核心解决行业通用痛点：原生ComfyUI生成长视频时显存爆满、内存溢出、程序闪退、低配电脑无法运行长帧任务等问题。

本工具通过**视频分段拆解、循环迭代生成、帧数据轻量化处理、分段合并渲染**核心技术逻辑，将超大时长视频任务拆分碎片化执行，从底层降低硬件资源占用，同时一站式覆盖图像、音频、提示词、场景、分镜、自动化运维全链路功能，是适配个人创作者、自媒体、AI工作室的全能型ComfyUI节点插件合集。

### 1.2 核心解决痛点（行业刚需）
- **硬件门槛高**：原生AI视频生成仅支持高端显卡，16G以下显存电脑无法生成10秒以上长视频
- **资源溢出报错**：长帧序列生成过程中，显存、内存持续堆叠，极易出现OOM报错、工作流中断、软件闪退
- **成片连贯性差**：手动分段生成画面断层、人物变形、场景跳转，过渡生硬
- **流程繁琐零散**：原生生态音视频处理、分镜管理、提示词批量配置无成套节点，需拼接多款插件，兼容性差
- **批量量产效率低**：无自动化调度、批量处理能力，人工重复操作多，无法规模化出片

### 1.3 适配用户群体
- **C端用户**：AI短视频创作者、自媒体博主、剪辑爱好者、低配电脑个人玩家、动画制作新手
- **B端用户**：AI内容工作室、短视频量产团队、电商内容制作团队、个人独立开发者、ComfyUI工作流定制师

## 二、核心技术原理（核心竞争力）
本工具区别于普通ComfyUI插件，核心优势为**长视频轻量化生成架构**，专属技术逻辑如下：
1. **长视频分段拆解机制**：自动将任意时长长视频，拆解为多段短帧任务，单次仅加载少量帧数据，避免显存一次性满载
2. **循环迭代生成逻辑**：支持多轮循环续帧生成，每段视频承接上一段画面特征，保障人物、场景、画风高度一致性
3. **潜变量轻量化处理**：内置潜变量清空、替换、提取节点，实时释放无效缓存，杜绝内存堆积溢出
4. **智能过渡帧优化**：帧生成器专属优化，自动补全段落过渡帧，彻底解决分段拼接画面断层、卡顿问题
5. **全流程资源管控**：生成过程实时监控资源占用，搭配自动任务调度、闲置资源释放，低配设备稳定运行不崩图

## 三、全功能模块详细说明
本节点包包含**八大核心功能模块**，覆盖AI视频创作全流程，所有节点相互适配、无缝联动，无需额外插件支撑。

### 3.1 长视频核心生成模块（主打功能）
专为解决长视频生成痛点研发，多版本迭代升级，兼顾稳定性、连贯性和画质。
- **多版本视频生成器（v1/v2/v3）**：v1基础稳定生成；v2优化人物一致性、画面比例适配；v3强化过渡帧效果，彻底解决长视频人物变形、画面跳变问题，支持超时长视频循环生成
- **帧生成器（v1/v2）**：AI智能补帧、续帧，修复长视频生成过程中的画面断层、帧率不稳定问题，适配分段循环生成逻辑
- **视频分段帧计算节点**：自动计算总帧数、分段帧数、起止索引，精准拆分长视频任务，无需手动算帧
- **视频分段器V1**：视频版的音频分段器V2，面板上选片、时间轴打点、按平均时长切段；目标模型可选「标准 / LTX / MiniMax」，标准按源帧率直接切（10 秒就是 10.000 秒那一帧收尾，下一段从下一帧开始），LTX 对齐 8k+1，MiniMax 对齐 17k+5。段边界全部落在帧号上，循环切完不漏帧、不重复取同一帧
- **视频分段加载**：按分段帧数列表 + 当前索引只解码这一段，输出视频帧和对应音轨。只传视频路径、用一段读一段，整条视频不进内存，修脸/补帧/超分/动作迁移这类逐段循环的流程用它
- **视频合并与渲染节点**：自动拼接所有分段视频，无缝合成完整长视频，保留原画质、帧率、音效
- **VR视频专属生成**：支持普通AI视频一键转VR视角，拓展长视频创作场景

### 3.2 轻量化资源优化模块（低配设备核心保障）
从底层优化显存、内存占用，是低配电脑跑长视频的核心支撑功能。
- **潜变量系列节点**：支持潜变量清空、替换、帧提取、帧数统计，实时清理无效缓存，杜绝内存、显存堆积溢出
- **图像缩放降分辨率节点**：智能缩放素材尺寸，自定义画质阈值，在不影响成片效果的前提下，大幅降低资源负载
- **数据类型转换节点**：整型浮点自动适配转换，优化模型运算逻辑，减少无效资源消耗

### 3.3 全维度音频处理模块
配套长视频生成，实现音频同步分段、剪辑、合并，音画完全同步。
- **多模式音频加载**：单音频加载、批量多音频加载，适配多镜头、多分段视频配音需求
- **音频智能分割**：按时长均等分割音频，匹配视频分段生成逻辑，音画时长精准对应
- **音频帧读取与预处理**：单独处理音频帧数据，修复长视频配音卡顿、音画不同步问题
- **音频合并合成**：自动拼接分段音频，适配长视频成片，支持多音轨叠加

### 3.4 批量图像素材管理模块
适配图文转视频、帧动画、素材批量预处理场景，支撑长视频批量量产。
- **图像批量/单张加载**：高速加载本地素材，支持批量导入、统一管理，适配多镜头创作
- **双版本图像管理器（v1/v2）**：v1基础素材管控，v2优化批量处理逻辑、修复素材加载BUG，提升批量出片稳定性
- **图像尺寸自定义配置**：预设多类视频尺寸模板，支持自定义分辨率，适配短视频、长视频、横纵屏各类场景

### 3.5 提示词智能运维模块
解决长视频多镜头提示词繁琐配置问题，支持批量、分段、动态提示词调度。
- **多提示词编辑器/加载器**：支持多组提示词批量导入、分段匹配不同视频镜头，无需手动反复修改
- **提示词优化节点**：智能润色、适配AI生成模型，提升长视频每一段画面的画质统一性
- **提示词中继编码**：优化提示词传输逻辑，避免长工作流提示词丢失、失效
- **多行文本加载**：支持长文案、分镜文案批量导入，适配故事机长视频创作

### 3.6 场景与分镜故事板模块
主打长视频结构化创作，支持多场景、多分镜连贯生成，杜绝画面场景错乱。
- **双版本场景加载/管理器**：统一管控视频场景风格、画面色调、场景元素，保障长视频全程场景统一，避免频繁跳变
- **LTX场景收集优化**：适配主流AI视频模型，解决长视频多场景生成错乱、元素丢失问题
- **故事板创建与加载**：支持自定义分镜脚本，按分镜自动生成连贯长视频，适配剧情类、动画类长视频创作
- **影视剧场流（场景管理/数据解析）**：流式管理影视级多场景数据，逐场景解析台词、素材、角色音色与音频，实时打印执行进度，适配短剧、影视解说长视频创作

### 3.7 自动化运维辅助模块
适配批量量产、长时间渲染任务，解放人工，提升自动化效率。
- **可配置自动关机功能**：长视频批量生成完成后，自动触发设备关机，节省设备能耗，适配通宵批量渲染场景
- **生成全局控制器**：统一调度帧生成、视频渲染、音频合成全流程，精准控制任务起止索引，避免漏帧、错帧
- **视频预览与纠错**：实时预览分段成片，提前排查画面BUG，减少无效渲染，提升长视频成片率
- **通用视频保存V1**：帧序列 + 可选音轨直接合成 mp4，不绑任何模型；修脸、补帧、超分这类「帧原样走一遍」的流程用它，帧率默认 24、可直接接原片帧率，不接音频就出无声视频

### 3.8 MiniMax H3 本地音视频生成模块
专为本地 MiniMax H3（Hailuo）模型深度定制，无需第三方云端即可完成提示词驱动、首尾帧锚定、多参考音视频注入的图生视频全流程。
- **MiniMax图生视频**：提示词 + 首尾帧关键帧（几何锚定）驱动 H3 生成；参考图片/视频/音频按官方 <Picture/Video/Audio N> 编号注入，支持外置音频作音色参考、原音频锁定或系统生成
- **MiniMax视频保存（v1/v2）**：H3 输出帧序列 + 音频直接合成 mp4，过渡帧与过渡帧音频同步输出，供下一镜头循环衔接；v2 为固定帧率/目录的精简版
- **MiniMax帧数计算器**：按音频时长自动对齐 H3 的 17k+5 帧网格（24fps），输出视频/音频潜变量时长，杜绝逐段舍帧累积误差
- **MiniMax音频分段加载**：长音频按分段时长切出当前段并对齐 H3 帧网格，供长视频逐段循环生成
- **MiniMax块缓存加速**：采样早期缓存 DiT 块输出，后期复用，显著降低显存占用、提升生成速度

### 3.9 素材库（网页版素材管理）
把 `ComfyUI/fxai` 整个产出目录做成一个网页，随时浏览、预览、整理，不用再靠资源管理器一层层翻。

- **入口**：`http://127.0.0.1:8188/fxweb`（就挂在 ComfyUI 自己的端口上，不额外起进程、不额外占端口；接口在 `/fxweb/api/*`）
- **看**：根目录五个分类（音频 / 图片 / 视频 / 提示词 / LoRA）带数量与体积总览；图片显示缩略图，视频显示首帧，音频/文本给图标；支持网格与列表两种视图、按名称/时间/大小排序、按类型筛选、跨子目录搜索文件名
- **预览**：图片看大图、视频直接播（支持拖进度条）、音频直接听、文本直接读，底部可重命名 / 移动 / 下载 / 删除
- **整理**：卡片勾选批量移动 / 下载 / 删除；删除先进回收站（可恢复、可彻底删、可一键清空），不会一失手就没
- **上传 / 新建文件夹**：直接复用本节点包已有的 `/fxai/image/upload`、`/fxai/audio/upload`、`/fxai/video/upload`、`/fxai/folders/create`，命名规则与工作流一致（`001.png`、`003_名字.wav`）
- **页面私有数据单独存放**（`ComfyUI/fxweb/`，与素材目录分开，避免被其它管理软件连带清理）：
  - `fxweb/thumbs/` —— 缩略图缓存（WebP，原图 3MB 约压到 20KB），超过 60 天或 2 万个自动清理
  - `fxweb/trash/` —— 回收站
  - `fxweb/fxai.db` —— 任务记录（`completed_tasks`）与角色档案（`character_profiles`）SQLite 库
  - 旧版本的 `.fxai_thumbs/`、`.fxai_trash/`、`fxai.db` 曾放在 `<fxai>/` 下，现已迁出；旧文件若残留会被自动跳过
- **保护名单**：`PROTECTED_FILES`（`fxai.db` 及其 `-wal`/`-shm`/`-journal`）在 `resolve()` 层直接拦截，
  即使手动拼 URL 也不能读、写、改名、删除
- **注意**：素材库删除**不会**自动重编号（删一个不该让别的文件改名）；要重排素材序号请用工作流里的「应用」按钮（`/fxai/image/apply`）
- 实现：`fxai_assets_core.py`（路径安全 / 列表 / 缩略图 / 回收站）+ `fxai_assets_ui.py`（aiohttp 路由）+ `web/assets.html`（页面）

## 八、服务控制脚本（ctl.py / ctl.cmd）
放在节点包目录下，供启动器网页会话底部的「重启服务」按钮调用，跟节点包一起同步更新，不用在 ComfyUI 根目录另放一份。

```
ctl.cmd kill    按根目录 fxai.json 里的 port 结束服务进程（只停不重拉）
ctl.cmd start   按 fxai.json 的 api / app 前台启动（日志留在当前终端）
ctl.cmd where   打印识别到的 ComfyUI 根目录、配置文件、脚本路径和端口
```

脚本会自己向上找带 `fxai.json` 的目录当根目录（放在 `custom_nodes/fxai-toolkit/` 时向上两级即 `ComfyUI/`），
启动前把工作目录切到根目录，因此 `main.py` 里的相对路径不受影响。

### 9.1 本机 / 常规 ComfyUI 安装

**前提**：已装好 [ComfyUI](https://github.com/comfyanonymous/ComfyUI)，建议 **≥ 0.30.0**（MiniMax H3 相关节点需要较新的本体）。三种装法任选其一：

| 方式 | 操作 |
|---|---|
| ComfyUI-Manager（推荐） | 装好 [ComfyUI-Manager](https://github.com/Comfy-Org/ComfyUI-Manager)，在节点列表里搜 `fxai-toolkit` / `凤希`，或用「Install via Git URL」填 `https://github.com/fxai666/fxai-toolkit` |

| ZIP 解压 | 在仓库页面 Code → Download ZIP（或 [Releases](https://github.com/fxai666/fxai-toolkit/releases) 里已发布的包）下载，解压到 `custom_nodes/`，目录改名为 `fxai-toolkit`；这种方式没有 `.git`，以后升级要删掉重拉 |

装完**重启 ComfyUI**。本包没有 `requirements.txt`，首次启动会自动补 `soundfile`、`psutil`（需要联网）；若启动日志出现 `ModuleNotFoundError: No module named 'xxx'`，用 ComfyUI 那个 Python 环境手动补包再重启：

```bash
<ComfyUI的python> -m pip install <缺的包名>
```

**验收**：启动日志里 `custom_nodes/fxai-toolkit` 加载无 `IMPORT FAILED` / `ModuleNotFoundError` → 节点搜索框能搜到「凤希AI - …」开头的节点 → 打开 `http://127.0.0.1:8188/fxweb` 能看到素材库页面 → `/fxai/health` 返回正常。四条都过才算装好。

**升级**：git 装的在 `custom_nodes/fxai-toolkit` 里 `git pull --ff-only`；zip 装的删旧目录重拉，并清掉旧 `__pycache__`；升级完照例重启。

### 9.2 仙宫云 GPU 实例安装

没有本机显卡、或想直接上 4090 跑全套工作流，用 [仙宫云](https://www.xiangongyun.com) 的 GPU 实例。按省事程度有三条路：

#### 方式 A：直接用官方公共镜像（最省事，拉起即用）

创建实例时在**公共镜像**里搜「**凤希AI-ComfyUI全自动短剧MV数字人生成**」（镜像 ID `9463d4ca-2f86-45cf-b0a3-a81ba6f3b27c`，类型 `community`），里面已经装好 ComfyUI、本节点包全部 `FxAi*` 节点和约 80 GB 的常用模型（千问2.1 / MiniMax H3 / YuE2 / Mel-Band RoFormer 等），不用自己克隆、不用等模型下载。开机后确认 ComfyUI 8188 能打开即可。官网也提供仙宫云镜像与代部署服务：在[官网](https://www.fxai.site)下载「凤希AI伴侣」，软件内下单即可；镜像若搜不到，走下面的方式 B/C。

#### 方式 B：已有实例，手动装节点

从仙宫云控制台拿 SSH 信息，连进实例后执行（路径按实例里 ComfyUI 的实际位置改）：

```bash
cd /root/ComfyUI/custom_nodes        # 没有 ComfyUI 就先克隆 https://github.com/comfyanonymous/ComfyUI.git
git clone --depth 1 https://github.com/fxai666/fxai-toolkit.git
# 重启 ComfyUI：控制台重启实例，或重启自己的启动脚本 / screen 会话
```

- 平台到 GitHub 的 TLS 偶发 `gnutls_handshake() failed`，**重试 2~3 次即可**；`codeload.github.com` 的 zip 下载在该平台常返 404，**请用 `git clone`，不要下 zip**。
- 依赖与重启规则同 9.1；容器里只有 `python3` 时，pip 要用 ComfyUI 那个 conda/env 的解释器，别用系统 pip。
- 装完必须重启 ComfyUI 才会注册节点；**不要在 ComfyUI 进程外裸 `import` 验证**，会误报 `PromptServer has no attribute 'instance'`，以重启后的节点列表 / `/object_info` 为准。

#### 方式 C：已装凤希AI技能包，一键部署

技能包里的 `fxai-xiangongyun-deploy` 会把「ComfyUI 本体 → 本节点包 → 模型」一次装完，可中断可续跑：

```bash
cd <凤希AI技能包>/fxai-xiangongyun-deploy/scripts
python deploy.py plan  --group all                                   # 先看要装什么、多大
python deploy.py probe -H <实例IP> -p <SSH端口> -u root -P <SSH密码>  # 体检 GPU / 磁盘 / 已有 ComfyUI
python deploy.py run   -H <实例IP> -p <SSH端口> -u root -P <SSH密码> --group all
```

常用开关：`--no-models` 只装节点、`--no-nodes` 只下模型、`--group img|music|mv|vocalsep` 分组下模型、`--variant pruned` 用剪枝版 H3 省空间、`--comfy-dir` 指定 ComfyUI 目录、`--parallel 3` 提速；没有 SSH 时用 `python deploy.py emit --group all --out xgy_deploy.sh` 生成自包含脚本粘到实例终端执行。SSH 凭据放本机 `~/.workbuddy/fxai_global.json`，**不要写进脚本或提交到仓库**。

#### 云端注意点

| 事项 | 说明 |
|---|---|
| ComfyUI 访问地址 | 平台给的容器域名把**端口写在主机名里**（形如 `https://<实例ID>-8188.container.x-gpu.com`），不是 `:8188` 后缀；以控制台 / `comfy-url` 给出的地址为准。控制台没放行公网时用 SSH 端口转发 `ssh -L 8188:127.0.0.1:8188 -p <端口> -N root@<ip>`，本机连 `127.0.0.1:8188` |
| 模型下载加速 | 把 `https://huggingface.co` 换成 `http://hf.x-gpu.com`（`HF_ENDPOINT` 同理）；整仓库可 `hf download`。返 401 = 平台未收录该模型，只能找仙宫云客服收录 |
| 磁盘 | 免费系统盘 = 镜像 + 100 GB × GPU 数；全量模型约 80 GB，下载前先看剩余空间。不够就分组下、挂数据盘，或「关机释放 GPU → 开机」免费扩容。停机省钱要**关机并释放 GPU**，「关机保留 GPU」照价计费 |
| 装完不生效 | 先重启 ComfyUI；再查日志是否缺 Python 依赖（整个包 import 失败会让所有 `FxAi*` 节点都不注册）；最后确认 ComfyUI ≥ 0.30.0 |

### 9.3 相关排障速查

| 现象 | 处理 |
|---|---|
| 节点全部消失 / `IMPORT FAILED` | 十有八九是缺依赖导致整包 import 失败，看 `comfyui.log` 里的 `ModuleNotFoundError`，补包后重启 |
| 「找不到模型」 | 本包部分节点读盘目录与常规约定不同，按节点提示的真实目录放模型 |
| Manager 报拉不到在线清单 | 云端 `raw.githubusercontent.com` / `comfyregistry.org` 可能不通，Manager 会退到 local mode，**不影响装节点**，装节点走 `git clone` |
| 节点数量不对 | 重启后查 `/object_info` 里 `FxAi*` 是否都在，别只看前端缓存，必要时强刷 `Ctrl+Shift+R` |
